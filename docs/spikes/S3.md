# S3 — Rust Stremio protocol client

**Status:** done (3 owner recordings pending) · **Dates:** 2026-10-14 → 2026-10-14 · **Plan:** [S3](../plan/phase-0-spikes.md#s3-rust-stremio-protocol-client) · **Spec:** [stremio-client](../specs/stremio-client.md) · **Decision:** D60, D61, D62, D63

## Question
Can our own Rust core talk to real Stremio addons, with no stremio-core code (D44)? Exit criteria:
- All resources and extras parse for 10 real addons, including configurable ones (AIOStreams first, Cinemeta, OpenSubtitles, Anime Kitsu, a TMDB addon, an IPTV/EPG addon).
- Streams arrive progressively: a CLI prints each addon's streams as soon as that addon answers.
- Recorded responses are saved as fixtures (secrets scrubbed) for the conformance suite.

## Verdict
**Yes.** A sans-IO client crate (`app-addons-stremio`, ~2.5k lines including tests) parses every response from 8 real addons with zero dropped items, routes requests the way stremio-core does, fans out with results in completion order, and honours the caching hints. The protocol is simple; the work is in **tolerance**. Addons disagree on scalar types and send legacy and new field names side by side. Recording real responses found one bug that synthetic tests would never have caught. The remaining 3 addons (AIOStreams, Comet, MediaFusion) need the owner's TorBox config and are recorded locally with one command each (D61). The tooling is in place; the recordings are the only thing left.

## What we tried
- **Layering (D60).** `crates/addons-stremio` has no runtime: models, manifest validation, routes, router, cache policy and fan-out (`futures::FuturesUnordered`) are plain code. Network access goes through a one-method `Transport` trait. `ReqwestTransport` (reqwest 0.13 + rustls, feature `reqwest`, default on) is the default and applies the per-request timeout. Tests use fake transports: a oneshot-gated fake proves completion order, and a counting fake with an injected clock drives the cache table.
- **Models.** Every object keeps unknown fields in `other` and re-serializes them unchanged. Lists drop bad items and report them (thread-local collector during a parse) instead of failing the response.
- **Dev CLI.** `crates/stremio-cli` (`stremio-cli manifest|catalog|meta|streams|subtitles`) loads manifests in parallel and prints each addon's answer as it arrives. Addon URLs can come from a file or env var and are never printed.
- **Recorder.** `stremio-cli record --name X URL` plans requests from the manifest, then trims, scrubs and anonymizes each body before writing and re-checks what it wrote. The anonymizer lives in `app-fixtures` and runs in CI's `check`.
- **Conformance.** `crates/addons-stremio/tests/conformance.rs` loads every `fixtures/stremio/*/index.json` and asserts the manifest validates and each response parses with nothing dropped.

## Surprises & gotchas
- **Serde aliases break on real data.** Cinemeta and TMDB send `episode` *and* the legacy `number`, and `title` *and* `name`, on the same video. `#[serde(alias)]` treats that as a duplicate field, which dropped every video of every series meta (8 per Cinemeta series, **3,230** for one TMDB talk show). Fix: no aliases; `Video::episode_number()` / `display_title()` fall back to the legacy field in `other`. Rule for all future models: **never use serde aliases for protocol fields.**
- **Scalar types are a free-for-all.** `imdbRating` and `releaseInfo` arrive as numbers or strings, and `fileIdx`/`videoSize` sometimes as strings. Lenient deserializers (`de.rs`) are needed from day one.
- **IDs are encoded like `encodeURIComponent`**: `tt0944947:1:1` goes on the wire as `tt0944947%3A1%3A1`, as stremio-core does. Extras use the same encoding per side (spaces as `%20`, not `+`).
- **Routing has sharp edges, so copy stremio-core exactly.** `idPrefixes: []` means *any* id; a resource object's `types`/`idPrefixes` do **not** fall back to the manifest's; only the first resource with a name counts; addon catalogs check extras. The first draft got three of these wrong (caught in review).
- **A query string on the transport URL is carried over** to resource URLs (stremio-core does a string replace of `/manifest.json`).
- **Empty manifests are legal.** An AIOStreams config with nothing connected serves `resources: []`, `types: []`. Stremio accepts that, so validation now warns instead of failing.
- **Freemium addons answer with ads.** Hyper unconfigured returns only paywall / "Go Premium" links as `externalUrl` streams with `name: null`. D36 (no ads) means the UI will eventually want a way to tell these apart from real external links.
- **Configurable addons may refuse without config**: Comet answers 403 and MediaFusion returns empty streams. Both need the owner's config to be useful test cases.
- **Finding a live, legal IPTV/EPG addon is hard.** Most community TV addons are dead (`*.baby-beamup.club`) or serve dubious sources. The M3U/EPG TV Addon pointed at the public iptv-org playlist works and is a good configurable case (base64 config in the path), but its EPG is off. No reachable addon with `epgProvider` and legal content was found, so EPG stays an open item.
- **Fixture size.** Full metas pretty-printed are ~15–30 KB each, and catalog previews from Cinemeta embed `videos`. Trimming lists keeps the repo light without losing shape.
- **Fixture filenames.** `:` isn't legal on Windows, so fixture paths use a stricter encoding than URLs (`encode_fs`).
- reqwest 0.13's default TLS is rustls with **aws-lc-rs**, which needs a C toolchain (fine on all three CI OSes). For the armv7 webOS build (S8) we may want rustls + `ring` instead. A transport is easy to swap because of D60.

## Consequences
- **Decisions logged:** D60 (sans-IO + `Transport`, reqwest default), D61 (owner records secret-bearing addons locally), D62 (anonymize stream/subtitle content), D63 (S3 conformance set).
- **Specs to update:** [stremio-client](../specs/stremio-client.md) is now `draft` with the full contract, the fixture format and the alias rule.
- **Plan changes:** M1.2 grows the conformance set to ~20 addons and adds configure flow, account import and EPG routes. S8 should check aws-lc-rs vs ring when cross-compiling.
- **Review (D58):** GPT-6.1-Sol round 1 found 4 privacy blockers in the recorder/anonymizer (query-string keys, tracker passkeys and subtitle release names surviving, secrets in printed parse errors and in file names) plus routing, cache and CLI issues. All fixed with regression tests; see PR #2.
- **Code to keep:** all of `addons-stremio` is written to keep, and Phase 1 builds on it as is. Missing pieces: persistent (SQLite) cache, per-addon concurrency limits, the background revalidation task (the crate already returns `Served::Stale`). `stremio-cli` stays as dev tooling.
